# WebChat 协议

本机自建的对话服务：一个回环 WebSocket，连上就能和助手聊天，回复按模型输出流式到达。不需要任何外部账号——它用你自己配置的模型和密钥，所以默认不启动，只在控制中心「网页对话（WebChat）」里手动开启，或存在已启用的 WebChat 账号时随应用启动。

- 地址：`ws://127.0.0.1:9881/`（端口可在代码里改；控制中心显示当前实际地址）
- 传输：WebSocket，**文本帧**，每帧一个 JSON 对象
- 鉴权：无。它只绑回环地址；能连上就意味着进程能访问本机，这与本机任何本地服务的信任模型一致

## 为什么要一个自定义协议

WebSocket 本身只给帧，不给语义。每帧放一个 JSON 对象，客户端不必在帧之上再造一层分帧约定：读到一帧就是一个完整消息，流式回复就是一串 `delta` 帧。

## 客户端 → 服务端

| type | 字段 | 说明 |
| --- | --- | --- |
| `message` | `text`（必填，去首尾空格后非空，≤ 4000 字符） | 一次对话回合。服务端回若干 `delta`，最后以 `done` 结束，或回一帧 `error` |
| `ping` | — | 存活检查，立刻回 `pong`，不碰模型 |
| `reset` | — | 清空**本连接**的历史，回一帧 `reset` 确认 |

任何其他情况都不是静默失败：未知 `type` 回 `error`，空文本、超长文本、非法 JSON、非对象 JSON 一律回 `error` 并说明原因。

```json
{"type":"message","text":"用一句话解释什么是 WebSocket"}
```

## 服务端 → 客户端

| type | 字段 | 说明 |
| --- | --- | --- |
| `welcome` | `protocol`（当前 1）、`maxPromptChars` | 连接建立后的第一帧，客户端据此判断版本 |
| `delta` | `text` | 回复的一个片段，可能只有一两个字 |
| `done` | `chars` | 本回合结束，附带整段回复的字符数 |
| `pong` | — | `ping` 的应答 |
| `reset` | — | `reset` 的确认 |
| `error` | `message` | 可读的原因；模型故障时只给异常类型名，不带请求 URL 或密钥 |

## 会话语义

- **历史按连接隔离**：每个连接维护自己的最近 20 条消息（10 轮），两个客户端互相看不见。
- **回合有序**：同一连接上的消息按顺序处理，上一条答完才处理下一条。
- **断线即遗忘**：历史只存在内存里，断开连接就没了；想保留请自己在客户端存。
- **reset 只清自己**，不影响其他连接。

## 一份最小客户端

```js
const socket = new WebSocket('ws://127.0.0.1:9881/');
let reply = '';

socket.onmessage = (event) => {
  const frame = JSON.parse(event.data);
  if (frame.type === 'delta') reply += frame.text;
  if (frame.type === 'done') console.log('完整回复：', reply, `(${frame.chars} 字)`);
  if (frame.type === 'error') console.error('失败：', frame.message);
};

socket.onopen = () => socket.send(JSON.stringify({ type: 'message', text: '你好' }));
```

控制中心自带一个可用的页面（启动服务后在控制中心点「打开对话页」，或直接访问 `http://127.0.0.1:8080/chat`），它的源码就是按上面这套规则写的，可以当作参考实现。

## 边界与已知取舍

- **不支持**：二进制帧、分片（continuation）帧、压缩扩展、64 位长度帧。超过 64 KB 的帧直接拒绝，而不是截断后当成正常消息。
- **没有心跳超时**：服务端不会主动断开空闲连接。
- **不做 Origin 校验**：本地页面与脚本都要用，加校验只会误伤。真正的边界是回环绑定——局域网内其它机器连不上。
- **回复质量取决于模型**：这里的实现只负责把历史与提示词交给对话管线，不做额外的提示词加工。
