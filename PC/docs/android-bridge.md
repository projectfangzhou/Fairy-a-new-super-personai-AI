# 手机端：任务与待审批（PC 配对调用）

清单第五条的一部分：Android 使用原生移动优先布局，待审批任务作为分层入口；PC 配对调用只传递
用户选择的东西，不转发长期令牌。

## 一、手机能做什么

配对过的手机在「任务」标签页里可以：

- 看电脑上的任务列表（标题、状态、id、时间）；
- 看**等待你回答的**待审批与提问，逐条允许/拒绝，或输入文字回答；
- 刷新。没有任务时明确说"没有等待你处理的项"，不会留一个空屏。

每一步都作用在电脑上的**同一项**：回答走 `AgentControlCenter.Answer` / `AnswerText`，和桌面控制
中心、灵动岛回答的是同一个待决项。这里没有第二套审批机制，所以不会出现"手机上批准了、电脑还挂着"
的局面。

## 二、权限与内容边界

两个开关，默认都关，且各自独立：

| 开关 | 含义 |
|---|---|
| `Sync.SummarySyncEnabled` | 手机可以读**任务摘要**（只有 id/标题/状态/时间） |
| `Sync.PairControlEnabled` | 手机可以读任务列表并**替你回答**待审批 |

分开是有意的：读摘要和代答是两种权限，勾一个不该顺带给出另一个。控制中心「手机任务摘要」区块里
两个勾选框并排，保存时各自提交。

鉴权沿用配对下发的令牌（`X-From-Device` + `X-Device-Token`），设备名不算凭据。未配对、令牌失效、
开关关闭，分别给出不同的错误，手机上显示成人话（"电脑上没有开启…" / "令牌已失效，需要重新配对"）。

内容边界上有两处刻意的不同处理：

- **任务标题会抹掉路径**再下发（标题可能带客户名或目录）。
- **待审批的提示文本不抹路径**，只截断到 300 字。因为用户要靠它做决定，"写入（路径已省略）"等于
  让人盲签。这条差异来自各自的目的：摘要是告知，审批是决策。

## 三、Android 侧

| 位置 | 作用 |
|---|---|
| `Services/PairedDeskService.cs` | 取 `/desk`、提交 `/desk/answer`；把 403 的 `error` 码翻译成人话；没有越权字段 |
| `Pages/TasksPage.xaml(.cs)` | 新的「任务」标签页：待审批卡片（允许/拒绝，或输入框回答）+ 任务列表 |
| `AppShell.xaml` | TabBar 变成 对话 / 任务 / 设置 —— 聊天仍是主入口，任务与设置是分层入口 |
| `MauiProgram.cs` | 注册 `PairedDeskService` 与 `TasksPage` |

PC 侧对应 `Services/PairedTaskBridge.cs`（纯逻辑，可测）与 `LanSyncService` 的两个路由 `GET /desk`、
`POST /desk/answer`。

## 四、验证

- PC 端 29 套测试合计 **1708 项断言全过**；本轮新增 `Tests/PairedDesk` 25 项，`Tests/Dashboard`
  258→261，`Tests/SummarySync` 58→62。
- Android 端 `dotnet build -f net10.0-android` 0 错误，并产出签名 APK（约 41 MB）。
- 页面：控制中心两个开关渲染与提交都有断言，内嵌 JS 过 `node --check`，16 个 section 配平。

覆盖的关键行为：开关关着时即使令牌有效也拒绝；另一个设备名不能借用令牌；任务标题里的路径不下发；
待审批的提示保留细节、风险类别随行；手机上回答会让 PC 上等待的调用真的拿到结果；同一项回答两次会
被明确报告而不是静默成功；空回答被拒；未知 id 被拒；视图序列化里没有任何令牌字段。

## 五、没做的

1. **Shizuku 没有接入**。它需要 `dev.rikka.shizuku:api` 的 AAR 绑定才能在 .NET 里调用官方 API，
   而这台机器上没有 Android 设备可验证。我不想为了"看起来接完了"去写一段调用未绑定类的代码——
   那会是又一个假协议。下一步要么做 AAR 绑定（有把 Android 构建弄坏的风险），要么先只把
   "已安装/已授权/未授权"和能力白名单写成可测的判定层。两条路都要先问你一句。
2. **帧率/内存没有测**。清单要求按实机帧时间、FPS、内存优化聊天/设置页；这必须有真机。
3. **没有真机联调**：手机上点允许、电脑上待审批消失这条链路，我只验到 PC 侧的桥接与 Android 侧
   的编译；`/desk` 的 HTTP 层也没有像 `/summary` 那样走真实端口测试。
4. **任务页只有读取与回答**，没有暂停/继续/停止（桥里已经带了 `CanPause`/`CanStop` 字段，接口还没写）。
